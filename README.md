# 求职助手 · resume_assistant

一个求职工作台：把简历、项目材料、岗位 JD 集中起来，帮你**改简历、判匹配度、语音模拟面试、复盘**。

线上示例：<https://resume.videotonote.cn>（手机号 + 短信验证码登录）

**「不编造」是它的第一原则。** AI 只用你确认过的材料；资料里没有的，它会明确说「需要你补充」，
而不是替你编一段简历。所有 AI 产出都是**草稿**，要你点确认才落到正式数据里。

## 能做什么

| 模块 | 做什么 |
|---|---|
| **材料库** | 上传简历截图 / JD 截图 / 项目文档 / GitHub 仓库 zip，自动解析成结构化事实，**每条都带出处** |
| **岗位** | 录入 JD，四层拆解（硬门槛 / 核心职责 / 加分项 / 隐性偏好）+ 匹配度打分 + 投递建议 |
| **简历** | 对着具体岗位给改写建议（🟢可直接采纳 / 🟡需要补充 / 🔴不建议写）；**没证据的会被代码强制降级**；也能和助手对话改 |
| **面试** | 按你的简历和 JD 出题；**语音模拟面试**——像打电话，会顺着你的回答追问（最多 2 层），不遍历题库；结束后五维评分 + 逐题拆解 + **标准回答案例** |
| **复盘** | 评分趋势对比、最危险的三处、逐题给你「面试官想听什么 / 差在哪 / 应该怎么答」 |

### 几个具体的点

- **JD 截图直接解析成原文**，不是一句摘要——匹配度分析吃的是完整 JD，漏一条要求就少判一条
- **匹配度是对着简历算的**，不是对着档案算的；默认用你最近更新的那份，也可以手动选
- **面试官按话题编号判重**，不会换个说法把同一道题再问一遍
- **语音首字节约 0.45 秒**（流式合成，边生成边播），不是等整段合成完才出声

## 快速开始（本地）

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env
# 填这几项：
#   DEEPSEEK_API_KEY / DASHSCOPE_API_KEY   两个 AI 服务的 key
#   ADMIN_PHONE                            管理员手机号（登录靠它）
#   SECRET_KEY                             python3 -c "import secrets;print(secrets.token_urlsafe(48))"

./run.sh                  # http://127.0.0.1:7870
```

首次启动会自动建管理员账号。**没配短信服务也能用**：验证码会打印到服务端日志。

手机要用麦克风必须走 HTTPS（浏览器只在安全上下文里给麦克风权限）：

```bash
./run.sh --https          # https://<局域网IP>:8443，自签证书
```

## 登录：手机号 + 短信验证码

**没有密码。** 手机号即账号，首次登录自动注册。

| | |
|---|---|
| 验证码 | 6 位数字，5 分钟有效 |
| 重发间隔 | 60 秒（界面倒计时与它对齐） |
| 每小时上限 | 同号 8 条 |
| 一次性 | 用过即废；重新发送会作废旧码 |

短信走阿里云（`ALIYUN_ACCESS_KEY_ID` / `_SECRET` / `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE`
四项齐全即启用真实短信）。**缺任意一项就退回「把验证码打进服务端日志」**——
开发环境和资质还没批下来的内测期都能照常用。

> 验证码**不会**通过接口返回给前端（那等于没有验证码）。本地调试可以开 `SMS_DEV_MODE=1`。

## 部署

完整步骤见 **[`部署文档.md`](部署文档.md)**，包含备案、短信资质、故障排查、以及
「把自己锁在门外」时的三条救急后路。

```bash
git clone https://github.com/Alex-original/resume_assistant.git
cd resume_assistant
cp .env.example .env && vi .env
bash scripts/deploy.sh          # 检查配置 → 起服务 → 等健康检查 → 验证鉴权 → 打印访问地址
```

两种对外方式，按服务器情况选：

| 情况 | 用哪个 |
|---|---|
| 服务器上**已经有 nginx** 在跑别的站点 | `docker-compose.behind-nginx.yml`，应用只绑 `127.0.0.1:7870`，由现有 nginx 反代 |
| 干净的服务器 | `docker-compose.yml`，自带 Caddy 自动签证书 |

> ⚠️ **域名不能带下划线**。`resume_assistant.example.com` 这种签不出证书——
> 公共 CA 一律拒绝含 `_` 的主机名。用 `resume.example.com`。

## 几条设计取舍

### 为什么一人一个数据库文件

数据隔离有两条路：给每张表加 `user_id`，或者一人一个 `.db` 文件。

这个项目选了后者。因为代码里是**手写 SQL**，前者只要漏一处 `WHERE user_id = ?`
就是数据泄露；文件级隔离则是**结构上不可能串**，而且业务代码一行都不用改
（当前用户 id 放在 `ContextVar` 里，`db.session()` 按它选库）。

### 为什么题库不是流程表

早期的实现是"按顺序遍历题库"，结果是面试官像在念稿子。
现在题库只是**弹药库**：由模型决定「追问 / 换话题 / 结束」，
代码只强制两条硬规矩——一次只问一个问题、追问最多 2 层。

### 为什么判重按编号不按文字

要求面试官「用自己的话问，不要念题库」之后，出现了一个反直觉的 bug：
它换了个说法问同一道题，而判重是拿"问出来的原话"和"题库原文"比，
永远对不上，于是同一道题被反复问。

现在按**话题编号**判重，再补一层相似度兜底（中文按字符 2-gram，
阈值 30% 是量出来的：同一件事 40%~89%，相关但不同 ≤20%）。

### 为什么流式语音

原来整段合成再下载，59 字的问题要 **3.25 秒**才出声——这就是"生硬"的物理来源。
换成 realtime WebSocket 边生成边吐 PCM 后，首字节 **0.45 秒**。
nginx 配置里必须 `proxy_buffering off`，否则缓冲会把这个优势吃掉。

### 为什么「我的档案」被删掉了

最初设计了一套「档案字段逐条确认」，结果一份简历能拆出 **121 条**待确认——
没人会点。而且没确认的事实 AI 看不见，等于越不点、AI 越笨。

现在确认的单位是**材料**：「这份材料我传的、解析得对」一句话就够。
没核对过的事实 AI 也能看到，但会标注出来、用到之前先问你。
